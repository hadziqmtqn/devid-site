---
title: HTTPS
description: "The local certificate authority, and tools with their own trust store."
---

HTTPS needs no manual steps:

- **On first start:** the daemon creates a local certificate authority, "Devid Local CA". It is name-constrained to `.test`, so it cannot be used for any other domain.
- **During setup:** on macOS, `devid setup` adds the CA to the System keychain. On Linux, it adds the CA to the system store, to Chrome's database and to each Firefox profile (see [Linux](/docs/linux#browsers)).
- **Per site:** each site gets a certificate when it is linked or parked. Devid renews it 30 days before it expires.
- **Browsers:** on macOS, browsers that use the keychain (Safari, Chrome, Brave) trust these certificates. On Linux, Chrome, Brave, Edge and Firefox do.
- **Devid's PHP and Composer:** they use `~/.devid/ca/cacert.pem` (the macOS bundle plus the Devid CA), so HTTP calls from one `.test` site to another work.

Some tools use their own certificate store:

| Tool | What to do |
|---|---|
| Firefox | On macOS it usually reads the keychain (`security.enterprise_roots.enabled`). On Linux, setup adds the CA to each profile; run `devid setup` again for a new profile. If it warns, import `~/.devid/ca/devid-ca.crt` under Settings → Privacy & Security → Certificates. |
| Node.js | `export NODE_EXTRA_CA_CERTS="$HOME/.devid/ca/devid-ca.crt"` |
| Python (requests) | `export REQUESTS_CA_BUNDLE="$HOME/.devid/ca/cacert.pem"` |
