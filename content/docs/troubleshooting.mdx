---
title: Troubleshooting
description: "devid doctor, common problems and reporting a bug."
---

Start with `devid doctor`. It checks every part of the installation and prints a fix for each problem:

- `PATH`;
- the LaunchAgent on macOS, or the systemd user unit on Linux;
- the daemon, DNS, the web server and PHP;
- the system setup;
- whether ports 80/443 really reach the web server;
- `.test` resolving;
- the CA;
- Valet;
- Mail, when it is on.

| Symptom | Fix |
|---|---|
| `php` is still Homebrew's or another one | Open a new terminal (or `exec zsh`). `~/.devid/bin` must come first on `PATH`. `devid path` shows whether the line is in `~/.zshenv` and `~/.zshrc`. |
| `php8.4`, `nginx` or `mailpit`: command not found, in a terminal or an editor | Run `devid path on`, or Settings › Terminal › **Add to PATH** in the app, then open a new terminal. These commands come with 0.16: on an older Devid, run `devid self-update` first. |
| "daemon is not running" | Run `devid setup` again. It is safe to repeat. Logs: `~/.devid/log/daemon.log`. |
| `.test` does not resolve, or ports 80/443 do not answer | Run `devid helper status`, then `devid helper install`. |
| Sites stop answering on 80/443 after Docker, OrbStack or UTM starts. `devid doctor` says ports 80/443 do not reach the web server; since 0.14, the app shows a banner and the menu-bar icon turns red. | Another app switched pf off on loopback: macOS Internet Sharing does this when a VM network starts. Run `devid helper install`. Since 0.14 it turns pf back on for loopback. |
| A site shows the wrong PHP version | Run `devid sites` to see each site's version, then `devid isolate <version>` inside the project. |
| A Laravel page shows no styles or scripts in Safari, while Chrome shows it | Vite runs on plain HTTP, which Safari blocks on an `https://` page. Set `APP_URL=https://<site>.test` in `.env`, then start Vite from Devid (0.18 or later). See [Laravel and Vite](/docs/laravel-vite). |
| The certificate is not trusted | Run `devid helper install` to trust the CA again, then restart the browser. |
| Mail does not start: its port is in use | `devid mail` names the program that holds it. Pick another port with `devid mail port <port>`, and set `MAIL_PORT` in your apps' `.env` to match. |
| Share says cloudflared is not found | Install cloudflared in one of the folders the error names. Without Homebrew, put the official download in `~/.local/bin` (from 0.16; with 0.15, also run `sudo ln -s ~/.local/bin/cloudflared /usr/local/bin/`). See [Local port and Share](/docs/tunnels). |
| An app's mail does not show up | Check that Mail runs (`devid mail`) and that the app's `.env` has `MAIL_HOST=127.0.0.1` and Devid's `MAIL_PORT`. `devid mail test` sends a test email. |

**Reporting a bug:** open a [Bug report](https://github.com/hadziqmtqn/devid/issues/new/choose) with your `devid --version`, macOS version and `devid doctor` output.
