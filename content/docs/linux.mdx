Devid runs on Ubuntu 24.04 and 26.04 from version 0.19, and on Arch Linux and the distributions built on it from version 0.20, on x86_64 (64-bit Intel or AMD). On Linux you use it from the command line and the [TUI](/docs/tui); the desktop app is for macOS only.

It is tested by hand on Ubuntu 24.04, on Arch Linux with KDE Plasma and on CachyOS with KDE Plasma and fish. Before each release, it goes through setup, a site over HTTPS and uninstall on Ubuntu and on Arch, on GitHub's runners.

## Install

Devid needs curl, `certutil` for the browsers and, on Arch, nftables. Install them, then run the install command.

On Ubuntu, which comes without curl (`certutil` is in `libnss3-tools`):

```sh
sudo apt install curl libnss3-tools
curl -fsSL https://github.com/hadziqmtqn/devid-binaries/releases/download/devid-latest/install.sh | sh
```

On Arch Linux, CachyOS and other Arch-based distributions (`certutil` is in `nss`; CachyOS has all three already):

```sh
sudo pacman -S --needed curl nss nftables
curl -fsSL https://github.com/hadziqmtqn/devid-binaries/releases/download/devid-latest/install.sh | sh
```

If a package is missing, setup names it, with `apt` or `pacman`.

Open Firefox once before you install, so it has a profile for setup to add Devid's certificate authority to. If you open it for the first time later, run `devid setup` again.

Setup takes the same options as on macOS (see [Install](/docs/install)), except `--gui` and `--server apache`.

## What setup changes

As you, in your home folder:

- `~/.devid`, with the `devid`, `php`, `composer` and other [terminal commands](/docs/terminal) in `~/.devid/bin`.
- The `PATH` line, in the files your login shell reads:
  - bash: `~/.bashrc`, and `~/.bash_profile` if you have one (Arch's default home does), otherwise `~/.profile`;
  - zsh: `~/.zshenv` and `~/.zshrc`;
  - fish, CachyOS's default shell: `~/.config/fish/conf.d/devid.fish`.

  Open a new terminal to use it. Apps you start from the desktop's menu see it after you log in again (checked on KDE Plasma with SDDM and with Plasma Login Manager).
- The daemon, as a systemd user unit: `~/.config/systemd/user/devid.service`. It starts when you log in and stops when you log out.
- Devid's certificate authority in the browsers' own databases, with `certutil` (see [Browsers](#browsers)).

With your password, once (sudo):

- `/etc/systemd/resolved.conf.d/devid.conf`: systemd-resolved sends `.test` lookups to Devid, and nothing else. Ubuntu and CachyOS run systemd-resolved already.
- Where systemd-resolved is off, as on Arch with NetworkManager, setup turns it on and points `/etc/resolv.conf` at its stub. It keeps the old file as `/etc/resolv.conf.devid-backup` and notes the change in `/etc/devid-resolved.state`. This needs NetworkManager. `devid uninstall` puts the file back and turns systemd-resolved off again.
- `/etc/devid-ports.nft` and `devid-ports.service`: ports 80 and 443 on `127.0.0.1` go to Devid's web server. The unit loads the rule at every boot.
- The certificate authority in the system store, for curl, PHP and other tools: `/usr/local/share/ca-certificates` on Ubuntu (`update-ca-certificates`), `/etc/ca-certificates/trust-source/anchors` on Arch (`update-ca-trust`).

A firewall such as UFW, which CachyOS turns on, needs no change: Devid's DNS and web server listen on `127.0.0.1` only.

`devid setup --dry-run` lists the steps without changing anything, and `devid uninstall` takes all of them back (see [Uninstall](/docs/uninstall)).

## Browsers

Most browsers on Linux keep their own certificate databases. Setup adds Devid's certificate authority to each one:

| Browser | Where the CA goes |
|---|---|
| Chrome, Chromium, Brave and Edge, from Ubuntu's `.deb` or Arch's packages | `~/.pki/nssdb`, which they share |
| Firefox: Mozilla's own build, Ubuntu's snap and Arch's package | Each profile's own database, in `~/.mozilla/firefox` or, with newer Firefox, `~/.config/mozilla/firefox`. A profile Firefox makes later needs `devid setup` again |
| Chromium as a snap | Its own database, which Devid does not cover yet |

On Arch, Firefox and Chromium from Arch's packages also read the system store, through p11-kit. Setup also adds the CA to the profiles of Firefox from Flathub, which has not been tested with Devid.

`devid doctor` checks Chrome's database and each Firefox profile, and names the profiles that lack the CA.

## Flatpak apps and terminals

- Apps installed as Flatpaks, for example from KDE's Discover, run in a sandbox and do not see programs outside it, Devid's `php` included. Editors from your distribution's packages (or the AUR) do.
- Discover installs Konsole as a Flatpak, which always starts in your home folder. The TUI's **open in Terminal** action needs a terminal that opens in the site's folder, so install one from your distribution's packages, for example `sudo pacman -S --needed konsole` or `gnome-terminal`. Arch's KDE install (`archinstall`'s KDE profile) comes without a terminal of its own.

## Not on Linux yet

- The desktop app.
- Apache. Use nginx, the default, or Caddy.
- Linux on arm64. Debian, Fedora and other distributions are not tested yet, and distributions without systemd (Artix, Void) are not supported.
